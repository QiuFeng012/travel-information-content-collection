# 广州 · 地点信息图

广州的**地点信息集合 + 行程规划**单页站点。给自己的旅游规划用，不是地图 App 的替代品——它解决的是「这几个点值不值得串成半天」这件事。

目前的数据以珠江新城 CBD 为主，另有跨区的点。地图初始视野会自动框住全部地点，往任何一个区加新点都不需要改代码。

纯静态，零依赖构建，双击 `index.html` 就能跑。**手机上可以加到主屏幕，当独立 App 用，断网也能打开。**

---

## 快速开始

| 方式 | 怎么做 | 适合 |
|---|---|---|
| 直接打开 | 双击 `index.html` | 快速看看、改数据 |
| 本地服务器 | `node tools/serve.mjs` | 手机连同一 Wi-Fi 真机测试（会打印局域网地址） |
| 部署上线 | 见下面「部署到手机上能打开的网址」 | 随时随地打开 |

没有构建步骤，没有 `node_modules`，没有 API Key。地图瓦片和 Leaflet 来自网络，但**首次打开后会被 Service Worker 缓存下来**——之后即使没信号，地点列表、详情、编辑全都能用，逛过的区域底图也还在。

### 部署到手机上能打开的网址

仓库里全部是相对路径，放在任何子目录下都能用。

**方案一：GitHub Pages（零配置）**

仓库 Settings → Pages → Source 选 `Deploy from a branch`，分支 `main`、目录 `/ (root)`，保存。一两分钟后：

```
https://<你的用户名>.github.io/<仓库名>/
```

`.nojekyll` 已经放好了，不需要额外设置。缺点是 `*.github.io` 在国内经常连不上或不稳定。

**方案二：Cloudflare Pages（国内可达性通常更好）**

[Cloudflare Dashboard](https://dash.cloudflare.com/) → Workers & Pages → Create → Pages →
连接到这个 GitHub 仓库。构建设置全留空（Build command 空、Build output directory 填 `/`）。
之后每次 `git push` 会自动重新部署。拿到的是 `<项目名>.pages.dev`。

**手机怎么用**

用手机浏览器打开上面任一地址，然后：

- **iOS Safari**：分享 → 添加到主屏幕
- **Android Chrome**：⋮ → 添加到主屏幕 / 安装应用

之后从主屏幕图标进去就没有地址栏，跟原生 App 一样。底栏中间有「地图 / 列表」切换按钮。

## 界面怎么用

- **手机上是单栏**：默认显示列表，点左上角「地图」按钮切到地图；在列表里点任意地点会自动切到地图并定位。
- **左侧列表 / 右侧地图**双向联动，点任一边都会选中同一个地点。
- **顶部筛选条**：行程分组（全部 / 未分组 / Day1–Day4）、类型（看 / 吃 / 喝 / 逛 / 公园 / 交通）、「≈ 待校准」。手机上这条可以左右滑动。
- **行程连线**：同一天的地点会按数组顺序用该天颜色连成虚线，标号就是建议顺序。
- **初始视野**：打开时自动框住全部地点。手滑平移走了，点右下角「⤢ 全部地点」拉回来。
- **标记形状**：地图和列表都用五角星。**实心星**=已排进行程（颜色=当天，星里是第几站），**空心星**=还没分组（星里是分类字：景 / 食 / 饮 / 购 / 园 / 铁）。星的大小在 `assets/app.js` 顶部的 `MK` 里调。
- **快捷键**（桌面）：`/` 聚焦搜索，`E` 切换编辑模式，`Esc` 关掉抽屉。
- **在高德打开**：详情页的按钮会带着地点名跳到高德 App / 网页版，导航交给专业工具。
- **导出**：下载 `places.js`（固化数据）、复制行程 Markdown、复制原始 JSON、恢复种子数据。

所有改动**自动存进浏览器 localStorage**，刷新不丢。但 localStorage 只在这台机器的这个浏览器里——想换设备或部署给别人看，用「导出 → 下载 places.js」覆盖 `data/places.js`。

## 目录

```
index.html              页面骨架
manifest.webmanifest    PWA 清单（名字、图标、独立窗口）
sw.js                   Service Worker，离线缓存
assets/style.css        样式
assets/app.js           全部逻辑（地图、筛选、编辑、导出）
assets/icons/           图标（由 tools/make-icons.mjs 生成）
data/places.js          地点数据 ← 你主要改这个
tools/check-data.mjs    数据自检
tools/check-pwa.mjs     PWA 自检（manifest / 图标 / 预缓存清单）
tools/make-icons.mjs    重新生成图标
tools/serve.mjs         零依赖本地服务器
```

改了 `sw.js` 的预缓存清单后，记得把文件里的 `VERSION` 加一，否则已经打开过的浏览器会一直用旧缓存。

## 加 / 改地点

直接编辑 `data/places.js`，刷新页面即生效。或者开编辑模式在网页里改，再导出覆盖。

字段定义：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一标识，不能重复。删掉的地点靠它记住 |
| `name` | string | 中文名 |
| `en` | string | 英文名 / 别名，可空 |
| `cat` | string | `看` `吃` `喝` `逛` `公园` `交通` 六选一 |
| `tags` | string[] | 自由标签，用于搜索和筛选 |
| `lat` `lng` | number | **WGS-84** 十进制度，见下节 |
| `v` | 0 \| 1 | 坐标可信度：`1` 已人工校准，`0` 是近似值 |
| `stay` | number | 建议停留分钟数 |
| `price` | number \| null | 人均元。`0` = 免费，`null` = 还不知道（显示「—」）。**别用 `0` 表示未知**，那会显示成「免费」 |
| `hours` | string | 营业时间 |
| `best` | string | 最佳时段 |
| `booking` | boolean | 是否需提前预约 / 订票 |
| `note` | string | 备注——规划时真正要看的东西 |
| `link` | string | 参考链接 |
| `style` | object | 可选，自定义标记外观，见下节 |

`window.PLACE_DAY_SEED` 是初始行程分组（`{ id: 'Day1' }`），网页里改完导出会自动重写这段。

### 自定义标记外观

地图上的标记默认是五角星，颜色按行程分组取。想让某个点更醒目，给它加一个 `style`：

```js
{
  id: 'xiaocang-canteen',
  name: '小仓食堂',
  // …
  style: { shape: 'pin', color: '#2f6f8f', size: 56 }
}
```

| 键 | 取值 | 说明 |
|---|---|---|
| `shape` | `star` `pin` `circle` `square` `diamond` `hex` | 默认 `star`（五角星） |
| `color` | `#rrggbb` | 默认跟随分组：排进行程 = 当天颜色，未分组 = 黑白空心 |
| `size` | `16`–`72` | 地图上的边长像素。默认已排 36 / 未排 30 |

三个键各自独立，只写想改的那个。**网页的编辑模式里有对应的控件**（形状下拉、大小输入、取色器 + 「默认」按钮），不用手改文件；改完「导出 → 下载 places.js」就能固化。

两条设计上的约定，用之前先知道：

- **颜色只改颜色，实心 / 空心仍然只表示「有没有排进行程」**。所以一个没分组的点就算设了自定义色，它在图上依然是空心——描边和字用你的颜色。否则一改颜色就分不清哪些还没规划了。
- **`size` 只作用在地图上**，列表里的序号保持统一大小。列表是排版，跟着地图缩放会乱。

改完跑一下自检：

```bash
node tools/check-data.mjs
```

会检查 id 重复、分类拼写、坐标是否落在广州行政范围外、分组是否引用了不存在的 id，并汇报分布跨度和最远的点。离花城广场超过 40 km 会报警告（不是错，但通常意味着坐标打错了）。

## ⚠️ 坐标系（唯一容易踩的坑）

**`data/places.js` 里的坐标一律是 WGS-84**，也就是 GPS 原始坐标、手机定位给的坐标、Google Maps 的坐标。

国内地图底图用的是 **GCJ-02**（火星坐标），两者在广州差 **300–500 米**。珠江新城整个才约 6 平方公里——偏 400 米就是标错一栋楼。

本站的处理方式：`assets/app.js` 里内置了 `wgs84ToGcj02()`，显示时按当前底图自动决定要不要转换。

| 底图 | 坐标系 | 是否转换 |
|---|---|---|
| 高德矢量 / 高德卫星 | GCJ-02 | 转换 |
| OpenStreetMap | WGS-84 | 不转换 |

所以：**从高德 / 腾讯地图复制来的坐标是 GCJ-02，必须先转成 WGS-84 再填**，否则换个底图就错位。稳妥做法是别复制坐标——用编辑模式在地图上点选或拖动，站点存进去的一定是 WGS-84。

### 为什么所有点都标着「≈ 待校准」

种子数据的坐标是按地名位置估算的，误差可能在 100–300 米（跨区那条「小仓食堂」是照着高德底图的经纬网格量的，误差约 ±150 米）。**第一次正式用之前，请过一遍**：

1. 顶部点「编辑」
2. 左侧点开第一个带 `≈` 的地点
3. 点「在地图上点选坐标」，然后在地图上点准位置（或直接拖动地图上的点）
4. 点「完成」

校准后 `v` 自动变 `1`，`≈` 消失，`v: 0` 的标记也不再出现。筛选条上的「≈ 待校准」能直接筛出还没过一遍的点，清到 0 就说明数据干净了。

## 这一版有意没做

按 MVP 取舍砍掉的，不是遗漏：

- **导航 / 路线规划**——高德已经做得很好了，深链跳过去就行
- **顺路排序 / 步行时长**——真需求，但要路径算法，下一版再说
- **账号、云端同步、多人协作**——单人规划用不上
- **爬虫抓点评数据**——反爬加合规，成本远超收益
- **照片墙 / 游记**——跟「规划」不是一件事

## 已知限制

- 数据存在 localStorage，换浏览器 / 清缓存会丢（导出 `places.js` 才是持久化的方式）
- 高德的栅格瓦片地址没有走官方 API，个人自用没问题，要商用请换成高德官方 JS API + 自己的 Key
- 离线只能看到**你逛过的区域**的底图；没看过的地块在断网时是灰的（地点和列表不受影响）
- 想改完网页立刻在手机上看到，得等 Service Worker 换版本：改完资源把 `sw.js` 里的 `VERSION` 加一
- Service Worker 只在 https 或 localhost 下生效，`file://` 双击打开时没有离线能力

## 自检

```bash
node tools/check-data.mjs   # 地点数据：id 重复、分类拼写、坐标越界、分组引用
node tools/check-pwa.mjs    # manifest、图标尺寸、预缓存清单、SW 注册
node tools/make-icons.mjs   # 改了图标配色后重新生成 assets/icons/
```

改完记得跑一遍；仓库约定见 `AGENTS.md`。
